# Contributing

Thanks for helping make VoiceMerge9000 easier and safer for creators.

## Ground rules

- Do not commit voice-model binaries, copyrighted source clips, personal data, tokens, local paths, or deployment/account identifiers.
- Use fictional, stylized, public-domain, or authorized voice examples in tests and documentation.
- Keep provider integrations behind small adapters so the core workflow remains portable.
- Label heuristic or experimental output honestly. Speaker guesses always need human review.
- Prefer browser-local or local-companion processing. Any external upload must be explicit in the interface.

## Pull requests

1. Create a focused branch.
2. Run the checks below and report any dependency or hardware blockers honestly.
3. Explain the creator-facing behavior, privacy impact, and manual test used.
4. Do not include generated audio or model archives in the pull request.

## Development checks

Read [HANDOFF.md](HANDOFF.md) before choosing work. Install the development dependencies using the README, then run:

```sh
python -m pytest engine/tests -q
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

Use synthetic fixtures generated by tests. Real audio changes also need a permissioned end-to-end inference test and listening review; mock/copy conversion is not a substitute. Report CPU/GPU, model parameters, duration, loudness, oversampled peaks, and remaining audible defects without sharing private media or machine paths.

Before a commit, inspect `git diff --cached` and the staged filename list. Never use broad staging to sweep in local model downloads or diagnostics. New tests should protect failed-speaker behavior, retry isolation, stale results, checkpoint validation, and sample-accurate timing as applicable.
